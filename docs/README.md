# Moxymind Technical Task — Automated Test Suite

> Playwright (C#, .NET 8, MSTest) suite for Task 1 (saucedemo UI) and Task 2 (reqres API),
> generated by an agentic workflow built on Mastra.

## Prerequisites
- .NET 8 SDK
- PowerShell 7 (`pwsh`), required by the Playwright browser installer script
- Internet access to https://www.saucedemo.com and https://reqres.in

## Setup
```bash
dotnet build MoxymindTests/MoxymindTests.csproj
pwsh MoxymindTests/bin/Debug/net8.0/playwright.ps1 install chromium
```

## Run the tests
```bash
dotnet test --filter "FullyQualifiedName~UI"    # saucedemo only
dotnet test --filter "FullyQualifiedName~API"   # reqres only
dotnet test                                     # full suite
```

Visual Studio Test Explorer discovers the same tests (MSTest TestAdapter 3.6).

## Project Structure
```
MoxymindTests/
  MoxymindTests.csproj       MSTest 3.6 + Microsoft.Playwright.MSTest 1.63 project
  Pages/                     Page Objects, one class per page (LoginPage, InventoryPage, CartPage, CheckoutPage)
  Tests/
    UI/                      LoginTests, CheckoutTests, InventorySortingTests
    API/                     ListUsersTests, CreateUserTests
  TestData/users.csv         CSV fixture for the data-driven POST test (copied to output)
  Schemas/                   JSON schema for POST /api/users response (copied to output)
  Helpers/                   UITestBase, APITestBase, Credentials, CustomerDetails, ExpectedUsers, TestLog
docs/                        Agent-produced markdown artifacts (test plan, architecture, review, README)
```

## Test Cases

### UI (saucedemo.com)
- `LoginTests.StandardUserLogsInAndReachesInventory`: Login is the gateway to every feature; first smoke check.
- `LoginTests.LockedOutUserSeesErrorAndStaysOnLogin`: Verifies access control and user feedback for blocked accounts.
- `CheckoutTests.StandardUserCompletesPurchaseOfOneItem`: Covers the revenue path (cart badge, checkout form, order confirmation).
- `InventorySortingTests.StandardUserSortsByPriceLowToHigh`: Price sorting drives purchasing decisions; wrong order is easy to miss.

### API (reqres.in)
- `ListUsersTests.GetUsersPage2ReturnsPaginationAndExpectedUsers`: GET `/api/users?page=2`. Checks status 200, pagination fields (page 2, per_page 6, total 12, total_pages 2), data count consistency, the exact last names of the first two users, and field data types.
- `CreateUserTests.CreateUserReturns201WithIdAndIsoTimestamp`: POST `/api/users`, data-driven from `TestData/users.csv` (one test per row). Checks status 201, `id` presence, ISO 8601 `createdAt`, echoed `name`/`job`, response time under the configured limit, and NJsonSchema validation.

## The Agentic Workflow (how this suite was built)
The suite was produced by six agents with two human gates.

1. Brainstorm agent: discusses scope with the human and drafts the test plan.
2. Gate 1 (human): the human reviews and approves the test plan.
3. Architect agent: converts the approved plan into an architecture document with classes, selectors and constants.
4. Dev-UI agent: writes the Page Objects and UI tests from the architecture.
5. Dev-API agent: writes the API tests, CSV fixture and JSON schema from the architecture.
6. Review agent: checks the output against the plan and the brief and records issues in `docs/03-review.md`.
7. Report agent: produces the final report and this README.
8. Gate 2 (human): the human reads the review and decides whether to accept the output or rebuild.

## Reviewing & Rebuilding
```bash
npm run agents        # opens Mastra playground at http://localhost:4111
```

1. Start a Brainstorm chat in the playground and describe the scope.
2. Review the proposed plan and approve it.
3. Run the test-generation workflow. It runs architect, dev-ui, dev-api, review and report in sequence.
4. Read `docs/03-review.md`. Open review items are listed there and must be resolved before the suite is treated as final.

## Model configuration
Copy `.env.example` to `.env` and set `ANTHROPIC_API_KEY`.
`ANTHROPIC_SONNET` and `ANTHROPIC_HAIKU` can be overridden to pin different model versions.
